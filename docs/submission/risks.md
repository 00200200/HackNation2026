# Risks and existing mitigations

The references below describe the merged `main` branch. A mitigation is an implemented control,
not proof that the risk is resolved. Unimplemented controls are labelled **not mitigated**.
Saved outcome metrics are quoted in [architecture.md](architecture.md) directly from
[evals/results/latest.json](../../evals/results/latest.json); that run has `overall_pass: false`.

| Risk and failure scenario | Mitigation present in code, with file:line | Residual risk / absent control |
|---|---|---|
| Hallucinations: a model invents a quote, misstates a claim or labels a quotation incorrectly. | Extraction is instructed not to decide truth (`prawdowid/verifier.py:4`). `judge.verify_quotes` accepts only a matching span in the cited title/fragment and displays the source's own words (`prawdowid/judge.py:212`, `prawdowid/judge.py:221`). Verdicts follow `decide()`; conflicts and insufficient evidence lead to abstention (`prawdowid/judge.py:305`). The linked page is excluded from its own evidence (`prawdowid/rerank.py:119`). | Text occurrence cannot prove that a quote supports the claim. Semantic errors in extraction, relevance, stance and missing context remain possible. Fact Check titles may be the only evidence text. Independent human review and a correction/appeal workflow: **not mitigated**. Citation correctness is unmeasured. |
| Source bias: the selected publishers or copied agency reports skew the answer. | An explicit source allowlist (`prawdowid/websearch.py:52`), URL canonicalisation and exact-duplicate removal (`prawdowid/rerank.py:193`, `prawdowid/rerank.py:175`), and grouping of shared publisher, quote or agency origins (`prawdowid/judge.py:419`) limit repeated evidence. Archival/undated material gets limitations (`prawdowid/judge.py:468`). EUvsDisinfo has type `disinfo_database`, outside the types counted as sufficient alone (`prawdowid/websearch.py:63`, `prawdowid/judge.py:40`). | Allowlist selection and reliable-type weighting are team policy; they have no independent diversity audit. Google review results are not restricted to the web allowlist. Missing dates, stale cache entries and institutional/editorial bias remain. Measured bias across topics or viewpoints: **not mitigated**. |
| Privacy: a submitted claim, source passage or URL contains personal data and leaves the host or persists in a channel/log. | Regex and checksum masking (e-mail, IBAN/NRB, card, PESEL, phone; `prawdowid/privacy.py:79`) runs before the text reaches the extraction model (`prawdowid/verifier.py:436`), so masked claims/queries are what flows on to web search, Google and EUvsDisinfo. Every write to the check log is masked again (`prawdowid/checklog.py:48`, `:62`, `:66`, `:76`), and every `prawdowid`/`prawdowid.discord` log line, tracebacks included, goes through `MaskingFilter` (`prawdowid/privacy.py:99`, applied in `prawdowid/app.py:27` and `prawdowid/discord_bot.py:39`). One check is kept 30 days as a masked record (`RETENTION_DAYS`, `prawdowid/privacy.py`) and a session can delete all of its own records (`DELETE /api/sessions/{id}`, `prawdowid/app.py:155-162`; a web button). The bot uses slash commands without privileged message-content intent (`prawdowid/discord_bot.py:309`). | Names and addresses are outside the regex; an ordinary 11-digit number can still pass the PESEL checksum by chance. Evidence fragments and the fetched link page are never masked (public pages, quotes must match word for word). Discord has no delete command for its own messages, and replies are public to the channel (same `send` call, `prawdowid/discord_bot.py:297-301`, no `ephemeral` flag); Docker stdout logs sit outside the 30-day retention (container log driver). The session id is a bearer token (`X-Session-Id`, no other login): anyone who has it can read or delete that session's check log via the API. Provider-side retention once masked text reaches Anthropic/Google/Tavily/EUvsDisinfo is UNCONFIRMED. See [docs/privacy.md](../privacy.md) for the full call-site table. |
| Prompt injection: input or a retrieved page asks the model to change its output. | Registered data tags and separate instructions are used for extraction (`prawdowid/verifier.py:86`, `prawdowid/verifier.py:172`), reranking (`prawdowid/rerank.py:245`) and judgement (`prawdowid/judge.py:505`). Models are asked to ignore instructions inside data. Extraction and judge flags create security events without repeating attack wording (`prawdowid/verifier.py:416-417`, `prawdowid/judge.py:205`), shown by channels (`frontend/public/app.js:212-215`, `prawdowid/discord_bot.py:200-210`). Quote validation limits invented evidence. | Code pre-checks run apart from the models: a Polish and English phrase list on the input, the linked page and every retrieved page, plus StackOne Defender's pattern tier on retrieved pages (`prawdowid/injection.py`). They only report, never drop a page, and miss paraphrases; Defender's ML tier was not used because it rated a clean Polish page as high risk. Reranking has no security-event flag. The latest quick injection metric fails (`0.0`, target `>= 0.9`); earlier runs on other commits scored up to `1.00` (`WORKLOG.md`, `c190450`). Every run so far covers a single injection case, so none demonstrates broad resistance (see the cases in `evals/results/latest.json`). Reliable prevention of instruction following or event suppression: **not mitigated**. |
| Availability: a key is missing, provider is slow, rate limited or unavailable. | API rate limit (`prawdowid/app.py:89`) and timeout (`prawdowid/app.py:102`); bounded provider operations (`prawdowid/factcheck.py:70`, `prawdowid/euvsdisinfo.py:73`, `prawdowid/websearch.py:234`); per-claim deadline and bounded retry (`prawdowid/pipeline.py:66`). Total retrieval failure and deadline expiry give `not_checked`; extraction failure returns a technical notice (`prawdowid/verifier.py:442-461`). Containers have health/restart policies (`compose.yaml:4`); the check log and source cache already point at a writable `/tmp` path for the `nobody` user (`compose.yaml:16-18`). | Extraction shares the check deadline (`prawdowid/verifier.py:434`), as does link fetch. The pipeline maps judge-model failure to `not_checked` (`prawdowid/pipeline.py:263`); a failed retry judge can keep a first-pass result, with a warning, when first-pass candidates existed (`prawdowid/pipeline.py:107`). A successful empty provider can lead to abstention even while others fail. Global backpressure, provider failover and measured concurrent capacity: **not mitigated**. |
| Abuse: many clients exhaust the model budget or use malicious URLs and output text. | Input size validation (`prawdowid/app.py:51-59`) and IP rate limiting (`prawdowid/app.py:73`, `prawdowid/app.py:89`). User URL fetching checks public IPs on each connection, caps redirects/body size and rejects access barriers (`prawdowid/link.py:124-135`, `prawdowid/link.py:214-225`). Web evidence fetching now shares that same guarded fetch (`prawdowid/websearch.py:305-313`, `safefetch.get`), not a bare domain allowlist. Browser rendering uses text nodes (`frontend/public/app.js:48`); nginx sets CSP and overwrites forwarded IPs (`frontend/nginx.conf:8`, `frontend/nginx.conf:21`). Discord escapes user/source text (`prawdowid/discord_bot.py:63`), disables mentions and previews, and needs no privileged message-content intent (`prawdowid/discord_bot.py:297-301`, `:309`). | IP limits do not cover distributed clients; Discord users share one IP quota. Rate-limit state is local to a process. No authentication, per-user quota, global concurrency/spend cap or abuse reporting workflow: **not mitigated**. Discord replies are not ephemeral (same `send` call, no `ephemeral` flag), so visibility depends on the channel. |
| Unlicensed or stale archives: successful web fetches are cached without confirmed rights or deletion timing. | Own PostgreSQL retrieval is disabled (`prawdowid/pipeline.py:158`). The store's `licence` column is `not null`: an insert without an approved licence is refused (`prawdowid/cache.py:323`, `db/migrations/001_source_store.sql:20`), and it has expiry and cascade deletion (`db/migrations/001_source_store.sql:27`, `:32`); seeding invokes expiry deletion (`prawdowid/corpus.py:67`). robots.txt is checked for evidence fetches (`prawdowid/safefetch.py:147`). | The JSONL cache keeps `licence` optional, `None` by default (`prawdowid/cache.py:115`), and drops full text when it is unset, keeping metadata only (`prawdowid/cache.py:164`, `:167`); it keeps only 30 days (`prawdowid/cache.py:141`) and replaces the stored record per URL on every save (`prawdowid/cache.py:150`); it still has no per-domain refresh schedule. The database's own insert instead keeps the first-seen copy of a document id, `on conflict (doc_id) do nothing` (`prawdowid/cache.py:315`), and its expiry deletion is seed-triggered, not scheduled. Publisher restrictions include PAP and AFP; see [sources.md](sources.md). A scheduled database deletion: **not mitigated**; session deletion of the check log is shipped (row above). |

Code references are relative to `main` at the time of writing; use the named functions when
following them on a later commit. Proposed work is deliberately not described as a safeguard already delivered.
The draft materials contain no input transcripts, provider credentials or personal datasets.
